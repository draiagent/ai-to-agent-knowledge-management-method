# Promptless 操作手冊

## 啟動

選擇圖卡或上傳圖卡，提供資料，指定成果位置。代理讀取相同編號與版本的 VAC，確認目前工具能力及授權。使用者不必重新寫完整流程。

最小啟動資訊：選哪個任務、素材在哪裡、成果要放哪裡。只有決策不可缺少的資料才補問；可保留未知的欄位明示「未指定」。

## 執行

先確認可讀來源，再依步驟閱讀與分析。輸出事實、推論、建議及缺口。重要結論附相對檔名與章節／頁碼／時間戳，不得把檔名命中當成已讀內容。

每次狀態更新需有依據。對外通知、工作派送及追蹤工具未連接時，只產生交接文件，不宣稱已通知或持續監控。

## 例外

| 情境 | 行為 |
|---|---|
| 資料不可讀 | 列出檔案與失敗原因，要求替代格式或標記阻塞 |
| 圖卡與 VAC 版本不一致 | 停在版本確認，不猜測流程 |
| 缺少負責人／期限 | 標示未指定並加入待確認事項 |
| 來源相互矛盾 | 並列證據，依權威規則或交由人判斷 |
| 已授權的新檔產出 | 直接執行並記錄成果位置 |
| 超出操作授權 | 提供具體待執行動作，再尋求確認 |
| 自動修正兩次仍不通過 | 保存中間成果、缺口與下一步，標記阻塞 |

## 交接與完成

「待處理→進行中→待驗收→已驗收」為基本狀態；任何階段可進入阻塞。狀態轉移要有證據，不以生成文件當作驗收通過。

會議整理本身與會議衍生業務任務分開驗收：前者完成引用、清單與缺口；後者仍需責任人實作及驗收。

## 回存

原始來源、圖卡版本、任務紀錄、核准成果及修正原因一起保存。維護者確認後才更新共用圖卡。這是能力累積的回饋流程，不宣稱模型自行學會或永久記住。
