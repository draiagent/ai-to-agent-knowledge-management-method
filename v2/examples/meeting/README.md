# 會議紀錄→團隊行動：完整實作案例

本案例為虛構的企業內訓籌備情境，日期晚於本版發布日，僅用於教學演練，並非真實會議或執行成果。

## 資料

- [第一次會議](sources/2026-09-21.md)：提議 20 人，草案指派及未分工事項。
- [第二次會議](sources/2026-09-24.md)：確認 10 人、提交回報、授權承諾與問卷交接。
- [VAC 規格](vac.json)：輸入、權限、流程、交付及驗收。
- [參考輸出](outputs/reference-result.md)：決議、任務、缺口及驗收界線。
- [本次任務紀錄](run-record.json)：示範如何保存執行狀態。

## 演練方式

先將 VAC 與 sources/ 兩份文件交給 Agent，指定新產出存入自己的工作資料夾，暫不讀取參考輸出。任務為辨識決議、整理行動、保留來源、標記缺口。

代理先辨識輸入是文字，第 02 步採校對。按兩次會議的順序分析，保留發言編號。20 人屬提議；10 人為確認方案。不得捏造預算、活動日期、未提供的檔案連結或驗收結果。

完成後與參考輸出比較，使用 [驗收範本](../../templates/acceptance.md)；其中路徑由本案例目錄向上兩層對應 v2/templates。

## 三個關鍵判斷

1. 課程草案已回報提交，但沒有實際提交時間及成果檔，因此不能判定準時或驗收完成。
2. 小陳已確認接手，仍不代表問卷完成。
3. 預算及日期缺少責任人與期限，應留待確認，不由代理擅自分派。

## 成果回存

完成分析可交付決議表、行動清單、缺口及來源。業務工作仍須追蹤，直到各自驗收。案例未連接任何通知、排程或任務管理服務，因此沒有真實派送或監控。
