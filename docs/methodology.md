# Agent 時代的知識管理：從維護工具到創造價值

本文件由作者提供的論述整理與落地化而成，定位為實務方法論，不是已經實證所有效益的研究報告。改善幅度應透過各團隊試行驗證。

## 一、典範轉移：從資料整理員到決策者

知識管理容易出現目標錯置：本來要解決工作問題，最後卻把大量時間花在分類、標籤、插件及外觀設定。當這些工作沒有改善檢索或決策，它們就成為額外負擔。

AI to Agent 的主張是重新分配責任。人負責目標、價值、判斷與驗收；代理承擔可重複的檢索、轉換、整合與草稿工作。衡量問題從「我的系統有多精緻」改為「它幫我完成了什麼」。

這不是取消人工整理，而是將整理投入限制在能創造實際收益的部分。對需要精確分類、專業術語或法定保存規則的內容，人工設計仍有價值。

## 二、知識本質：可攜的資產底層

「資料夾即知識庫」強調資料不應完全依附某一介面。Markdown 可承載筆記與決策；PDF、Word 保留專業文件；圖片、影音保留原始脈絡。應讓來源與衍生成果分開，以免摘要取代原始證據。

在地保存可增加控制權，但不自動等於安全或長期可讀。仍須備份、確認還原方式及保留格式轉換路徑。若在地檔案送入雲端模型，處理過程仍可能離開本機。

不必為採用本方法論而全面搬家。既有以一般檔案保存資料的筆記工作流，可保留作為閱讀或編輯介面。先降低不必要維護，再決定是否更換工具。

## 三、AI Agent：知識的中間處理層

代理的價值在於把問題轉成搜尋計畫，選取相關來源，核對證據，再交付當下需要的形式。

一次合理的檢索應包含：確認可讀範圍、依名稱與內容找候選文件、閱讀相關片段、處理版本衝突、回答並標註來源。代理未成功讀取的檔案須列為缺口。

「隨用隨建」代表分類與關係可隨任務生成，不代表每次都要掃描全部檔案。小型庫可直接閱讀；大型庫可使用索引與分段檢索。索引是效率工具，不是必須由人日常手工維護的儀式。

費曼式學習可採四步：請代理用簡單語言解釋；自己不用原文重述；指出解釋中的空缺；回查來源後修正。只收下精煉答案，不能證明已理解。

## 四、三層分工：資料、代理與呈現

| 層級 | 穩定保存的部分 | 可按需變動的部分 |
|---|---|---|
| 資產層 | 原始文件、版本與來源 | 經核准的檔案更新 |
| 代理層 | 最小檢索與引用規則 | 任務規劃、候選來源及分析方式 |
| 表現層 | 必要的閱讀與輸出能力 | 表格、圖解、簡報與任務清單 |

「表現層退場」指它不再主導工作，不是取消視覺化。當圖表能幫助比較、理解或決策，就應使用；當它只是需要持續維護的裝飾，就應精簡。

## 五、README＋提示詞：最小可行操作系統

README 說明這個庫為何存在、資料在哪裡、哪些版本具權威性及如何引用。提示詞則說明這次要解決什麼、能讀寫哪裡、要交付什麼與怎樣算完成。

兩者職責不同：README 是較穩定的導航；任務規格是本次工作契約。README 不保證會被所有代理自動載入，應在任務開始時明確要求閱讀。

以會議為例：輸入兩次會議紀錄，輸出已確認決策、跨會議未決事項、風險與行動表。若負責人或期限缺失，就標示未指定，不可為了表格完整而捏造。

## 六、人類價值：思考、判斷與創造

思考是提出值得解決的問題；判斷是檢查證據、取捨風險與承擔決策；創造是將資訊轉成新的方案、產品、教材或服務。

代理讓人更容易接近知識，但不能替人決定所有價值。真正的成果不是收集更多資料，而是在可追溯的依據上完成行動，並把結果回饋到下一次工作。

## 可檢驗的承諾

本方法論預期降低無效維護、縮短取得可用答案的時間，並改善決策可追溯性。這些是試行目標，不是保證。若檢查與修正代理輸出的成本高於節省時間，就應縮小任務範圍、改善來源品質或保留人工流程。
