# 實作手冊

## 第一輪：用一個真問題試行

1. 選一個明確問題，例如「這兩次會議後，哪些工作仍未完成？」
2. 選取少量相關文件副本，記錄人工處理所需時間作為基準。
3. 填寫 README，說明文件用途、日期及權威來源。
4. 讓代理先確認可讀資料，回報缺少檔案或轉換障礙。
5. 填寫任務規格，要求輸出引用、未決事項及行動清單。
6. 抽查重要結論與所有決策依據，退回沒有證據的斷言。
7. 將通過驗收的結果存入 outputs/；人類確認的決策存入 decisions/。

## 日常循環

提出問題 → 找到證據 → 分析並呈現 → 人類驗收 → 採取行動 → 記錄結果。

新資料先保存來源，不必立即建立複雜分類。當重複出現同類問題時，再將已驗證流程存為提示詞或任務範本。

## 常見失敗與修正

| 問題 | 可能原因 | 修正 |
|---|---|---|
| 答案沒有來源 | 任務未要求引用 | 將來源定位列為驗收條件 |
| 引用了舊決策 | 權威版本不明 | README 指定定稿與撤回規則 |
| 總是說找不到 | 格式無法讀取或搜尋範圍錯誤 | 先確認抽取與可讀清單 |
| 花更多時間校正 | 任務過大或資料品質低 | 拆小任務並改善關鍵來源 |
| 改名後引用失效 | 缺少變更映射 | 保留舊新路徑對照並更新引用 |
| 整理再次失控 | 以完整分類為目標 | 只維護能改善當前任務的結構 |

## 衡量是否創造價值

先使用相似任務建立基準，再比較導入後結果。以下是指標定義，不是已取得的成效數據。

| 指標 | 計算方式 |
|---|---|
| 任務總耗時 | 提問、等待、核對、修正及交付時間總和 |
| 維護負擔 | 每週非內容創作的系統維護時間 |
| 引用可驗證率 | 抽查後確實支持主張的引用數／抽查引用數 |
| 行動完整率 | 含任務、責任人、期限或明確缺漏標記的行動數／全部行動數 |
| 成果可用性 | 接受、需修正、不可用，並記錄原因 |

分母為零時標示不適用；不要用零錯誤宣稱沒有風險。若連續幾次試行沒有改善，優先修正問題與資料，不急著增加工具。
